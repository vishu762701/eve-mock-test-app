## Limits and remaining verification

- Release requires actual authenticated student/admin smoke tests against the deployed Worker and the new Android APK. No available production user/admin token; cannot truthfully claim login-to-result/device end-to-end execution here.
- D1 registered-profile count is the real D1 users count, not an authoritative Firebase Auth directory count. Generated question totals use persisted question_count metadata; invalid tests remain flagged rather than deleting historical data.
- AI/media health means configuration present until the existing explicit AI test or real generation succeeds. No paid provider access/model/key validation performed. Existing model settings are preserved.
- Firebase Auth health checks public signing-key reachability only. Firestore/FCM availability and notification delivery explicitly show unavailable; media readiness checks bindings only. Authenticated routing itself also requires D1; a database outage can prevent the health screen request and is shown as request failure.
- Native UI, process death, offline work scheduling and account lifecycle require device/emulator smoke testing beyond parser/retry unit tests. Existing Home/Mock/Result segmented layouts are preserved.
- Older ownerless queue/session files are retained, but not automatically attributed or submitted under a signed-in user. Manual recovery must establish the original owner; no unsafe migration of unknown student data.
- Sessions delayed beyond existing server grace can save a result with counted=0; offline recovery does not bypass timing, attempt-limit, leaderboard or premium policies.
- Old started sessions without question snapshots use compatibility fallback. Only new/resumed populated sessions get immutable snapshot protection. History remains unpaginated; its SQL bind limit is fixed, but very large histories remain a scaling follow-up.
- Generation deduplication is per request key and exclusive per exam. Failed scheduled daily request keys require admin retry. Job retry uses current syllabus/prompt and the recorded count; provider partial questions are discarded, so generated count means successfully committed questions.
- Failure logs are best effort: disconnected devices and an unavailable D1 cannot always record events. They contain no private answer payload, UID, password, token or API key. Thirty-day cron cleanup and bounded pages apply to monitoring, not student records.
- Firebase dynamic admin emails and Worker D1 admin emails are separate existing stores. This repair does not invent automatic role synchronization. Email-based admins must have verified Firebase email ownership.
- Registration, logout, search, profile/media, notification delivery, explanation calls and full Firebase synchronization were source-reviewed, not all executed against live services. No blanket production-ready claim is made.

Local build setup required a full JDK (the supplied Java was a JRE), the system proxy trust store, and a larger JVM code cache for the in-process compiler. These are workspace-only validation settings. Existing AGP8.5.2 compileSdk36/deprecation warnings remain; no warning suppression or skipped test is used to claim success.
